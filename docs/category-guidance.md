# Category captioning and preparation guidance

Sources checked 2026-10-12. This document separates model/backend contracts from captioning heuristics. Recommendations are starting points; no caption template establishes trained quality. The Person pipeline retains its existing behavior.

## Category contracts

Object captions use the target trigger and an object class. Style captions use a style anchor and variable scene content. Concept captions use a concept anchor and preserve variable participant roles, spatial relationships and context. Built-in KEEP details are omitted; CHANGE details are retained when evidenced. The text formatter accepts only the selected category's fields, filters KEEP fields, preserves source qualifiers and supports relevant integral markings without importing Person's blanket lettering exclusion. Custom rules remain optional and cannot silently override conflicting built-in rules.

Coverage is descriptive, independent of caption omissions. Object checks cover visible target extent, viewpoints and settings. Style checks cover depicted content, composition and usable surface detail. Concept checks cover relationship visibility, participant-count classes and context. Repeated known tags can prompt a diversity review only for changeable attributes; unknown and stale suggestions are excluded. These are advisory distributions, not identity matching, style similarity, semantic curation or fixed diversity quotas.

Source observations, manual captions and coverage corrections remain recoverable. Changing category invalidates the applicable automatic caption policy; manual captions are preserved for review. Old non-person observations made with the person-oriented prompt require fresh vision before text-only processing. Inference results are not saved against a changed category/intent. Each export freezes its category policy version, intent, prepared geometry and captions.

## Official model and library guidance

### Krea 2 Raw

The [Krea model card](https://huggingface.co/krea/Krea-2-Raw) identifies Raw as the fine-tuning checkpoint. The [Diffusers Krea training guide](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_krea2.md) recommends Raw training with Turbo validation, gives a 1024 example, and recommends captioning variable content while omitting learned style details. It specifically favors a descriptive phrase for a style trigger; an object trigger can be a unique word paired with the correct class. LoRA Studio implements those caption distinctions and displays the descriptive-trigger recommendation without replacing saved triggers. Existing Raw training previews do not substitute for Turbo evaluation. The guide's example learning rate, rank and target-module advice belong to that trainer and are not blindly copied into AI Toolkit.

### Qwen Image 2.1

The [official model card](https://huggingface.co/Qwen/Qwen-Image-2.1) documents text-to-image and editing as distinct usages and native RGBA generation. The [Diffusers 2.1 training guide](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_qwenimage21.md) gives a 1024 training example, requires dimensions divisible by 32 and distinguishes descriptive text-to-image captions from paired editing instructions. The installed AI Toolkit adapter also uses a 32-pixel grid. LoRA Studio retains its RGBA preparation and captions the resulting image, rather than emitting editing commands. A 2048 inference example is not a requirement to train every LoRA at 2048. Transparency must not be guessed from checkerboard appearance.

### FLUX.1 Dev

The [official FLUX.1 Dev card](https://huggingface.co/black-forest-labs/FLUX.1-dev) uses descriptive text and documents prompt sensitivity. The [Diffusers maintainer's advanced LoRA guide](https://huggingface.co/blog/linoyts/new-advanced-flux-dreambooth-lora) includes style training with per-image captions and a trigger/class anchor, while explicitly describing its experiments as exploratory. LoRA Studio uses concise natural language, preserves caption ordering, and separates learned properties from variable context. Its 768 starting target remains configurable; the installed AI Toolkit example supports multiple resolutions, but this app deliberately freezes one selected area target per run. No new curriculum is silently enabled.

### SDXL

The [official SDXL card](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) and [Diffusers SDXL training example](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_sdxl.md) establish the model and a 1024 example. [AI Toolkit's SDXL documentation](https://ostris.com/docs/ai-toolkit/models/sdxl) describes its CLIP conditioning and backend behavior. LoRA Studio puts the trigger and essential content first in compact captions; it does not equate words with tokenizer tokens or truncate saved manual captions. Existing 768 starter settings and the conservative 64-pixel grid remain valid user-overridable preparation choices, not claims that SDXL requires 768 or a 64-pixel architectural minimum.

## Community and backend evidence

- [AI Toolkit dataset documentation](https://github.com/ostris/ai-toolkit#dataset-preparation) describes matching image/text sidecars and trigger handling. The installed `config/examples/train_lora_flux_24gb.yaml` confirms ordered captions (`shuffle_tokens: false`) and resolution buckets. LoRA Studio exports prepared PNG/text pairs, keeps caption order and disables random crop/scale/flip so the exported image matches its caption. These conservative choices protect product markings, directional relationships and composition. They are not universal claims that augmentation is harmful.
- [AI Toolkit Krea documentation](https://ostris.com/docs/ai-toolkit/models/krea2) and [Qwen 2.1 documentation](https://ostris.com/docs/ai-toolkit/models/qwen-image-2) were compared with the installed adapters. The local code confirms Krea's 16-pixel and Qwen's 32-pixel bucket grids. LoRA Studio continues to wrap that backend; it does not substitute Diffusers-specific training switches.
- [MonsterMMORPG's published FLUX style experiment](https://huggingface.co/blog/MonsterMMORPG/full-training-tutorial-and-research-for-flux-style) compares captioned and minimally captioned datasets with differing style consistency. Its outcomes vary with dataset and checkpoint. That supports checking consistency and comparing checkpoints, not declaring detailed captions or trigger-only captions universally best. This implementation retains editable, intent-aware captions and has no automatic aesthetic filtering.

No reviewed source provides a universal validated recipe covering Object, Style and Concept across all four models. The category checks are an engineering synthesis of visible-evidence rules, learning intent and dataset diversity practice. They deliberately avoid fixed image quotas, automatic semantic scores, guessed material composition and inferred actions. Source-specific example ranks, step counts and learning rates are not treated as a universal optimum.

## Validation boundaries

### Action / concept pipeline additions (2026-10-13)

The [Diffusers advanced DreamBooth guide](https://huggingface.co/blog/sdxl_lora_advanced_script) supports per-image custom captions, while [Minta Carlson's firsthand captioning observations](https://huggingface.co/blog/alvdansen/enhancing-lora-training-through-effective-captions) discuss distinguishing the trained concept from variable details instead of describing everything. These are starting points, not evidence that omission guarantees disentanglement. The existing Krea 2 and Qwen guidance above still governs their caption formats and model preparation. No universal action-caption recipe was found that supersedes explicit learning intent and visual review across all supported models.

Concept presets resolve Auto rules for pose, facial expression, camera angle, action, interaction, spatial relationship, lighting, composition, focus and visual effects. They preserve explicit choices and the original General defaults. Camera viewing direction is separate from crop/shot distance; body pose is separate from facial expression. Existing explicit framing and pose choices are carried into viewpoint and expression when migrating legacy concept projects. Preset selection is intent, not a visual classifier or proof that an image depicts that concept.

Both caption-provider routes preserve full observations and then extract short, evidence-linked variable facts. The concept trigger does not name a participant. KEEP details are omitted, actors and recipients retain their source order, qualifiers cannot be stripped, and missing scene content causes a retry or an explicit failure. Common pose/expression/viewpoint/focus leaks have narrow cross-field guards; arbitrary semantic concepts still need review. The formatter retains at most six complete facts. Source matching proves extraction consistency, not vision accuracy. Text processing cannot invent concept-presence coverage. Saved visual coverage is tied to the learning intent; changing the target invalidates it while retaining observations, edits and history.

The installed AI Toolkit configuration continues to use ordered image/text sidecars with random flip/crop augmentation disabled, preserving directional relations and the exact reviewed crop. No new training engine, automatic semantic curation, pose manipulation, face editing or trained-quality claim is introduced. Local validation uses isolated state, public source provenance and private review artifacts under ignored `internal-tests/`. Test samples can include drawings, diagrams or generated faces; they exercise the pipeline and are not a recommended training dataset. Watermarks, instructional overlays and small subject detail still require user judgment even when captions omit their text.

The live benchmark completed ten images each for tree pose, smiling expression, overhead camera angle, holding an umbrella, stacked objects, backlighting, balanced composition, shallow focus, snow-covered scenes and water reflections. All 100 automatic captions completed with matching frozen images and caption sidecars, across Krea 2 and Qwen Image 2.1 preparation profiles. Paired visual review led to fixes for dropped participant nouns, too little variable context, inferred demographic labels and common KEEP details leaking into other fields. Sparse extractions now retry, then retain an explicit review warning if still sparse.

Review also required 21 explicit caption edits for omitted subjects, unclear fragments and incorrect visual details; their automatic drafts and raw observations were retained. Ten additional provider-based visual spot checks exercised the advisory review route, but missed some errors found in paired inspection. This is evidence for an editable preparation/review workflow, not a 100% automatic caption-accuracy claim. These varied test sets are not curated training recommendations, and no GPU training or trained-concept quality evaluation was performed.

### Style pipeline additions (2026-10-13)

The current [Diffusers Krea 2 guide](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_krea2.md#captioning-for-style-loras) recommends describing variable content, omitting learned rendering traits and using a descriptive style phrase. [Black Forest Labs' FLUX.2 Klein tutorial](https://huggingface.co/blog/black-forest-labs/flux-2-klein-lora#caption-the-content-never-the-style) similarly separates content from style and explicitly permits captioned substyle controls. Its rare-token and training hyperparameter recommendations are model-specific; this application does not replace Krea's descriptive-trigger advice or change FLUX.1 into FLUX.2. [Minta Carlson's firsthand captioning observations](https://huggingface.co/blog/alvdansen/enhancing-lora-training-through-effective-captions) support selecting useful variable details instead of exhaustive descriptions; those experiments are guidance, not a universal result.

The implementation uses optional family hints, content-focused evidence extraction and conservative cross-field checks. Object colours/materials remain content; overall grading, grain, linework and rendering medium follow their own keep/change choices. A subject/form fact is required when subjects are changeable, avoiding captions that retain only a camera angle. Redundant subphrases are removed and automatic style captions retain at most six complete facts. Leading medium wrappers and selected rendering adjectives before subject nouns can be omitted from source matching without dropping counts or relationships; raw evidence remains unchanged. The same formatter runs after connected vision and dedicated captioners. It preserves raw observations, their warnings, previous drafts and manual edits. Source matching checks what the formatter extracted; it does not establish whether the vision observation was correct. Missing scene content causes a retry or an explicit failure instead of a trigger-only export.

The normal workflow reuses existing reversible, model-aware preparation and immutable exports. Family hints do not identify artists, prove style consistency, choose camera hardware, transform images or silently alter crop settings. Fine detail and border coverage remain advisory. Test image counts are validation sample sizes, not minimum training quotas. Live fixtures and qualitative review evidence stay in ignored `internal-tests/`; the reproducible suite uses authored synthetic evidence only.

A live local-provider benchmark used ten public images in each of five families: realistic photography, cartoons, drawings, watercolor and pixel art. All 50 completed final captioning and export with exact caption-sidecar agreement. Image/caption inspection exposed and led to fixes for lost subjects, mixed-in style words, hyphenated pixel-art labels, false transparency claims and repeated fragments. The realistic set is ordinary photography, not a ten-image Polaroid evaluation; instant-film borders/grain also have synthetic policy coverage. These batches deliberately include varied or repetitive content to exercise caption behavior and advisories, and are not recommended coherent training datasets. Browser checks cover desktop/mobile review and family persistence. No GPU LoRA training or trained-style quality evaluation was performed.

### Object pipeline additions (2026-10-13)

The default Object path uses the existing connected local vision provider for bounding-box localization, followed by a reversible crop and the selected caption provider. The [Qwen grounding cookbook](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/2d_grounding.ipynb) documents relative-coordinate grounding; LoRA Studio explicitly requests a 0–1000 coordinate system and rejects invalid boxes. It does not assume every vision model is an accurate detector or interpret a model's confidence as calibrated. Missing and ambiguous targets require manual selection, an explicit full-image choice or exclusion. An 8% crop margin is a configurable engineering default, not a model author's universal recommendation.

Optional loss masks follow [AI Toolkit's dataset configuration](https://github.com/ostris/ai-toolkit/blob/main/toolkit/config_modules.py) and [mask loader](https://github.com/ostris/ai-toolkit/blob/main/toolkit/dataloader_mixins.py). The installed loader matches mask/image stems, reads grayscale, applies aligned transforms and maps to `mask_min_value`; the trainer weights loss when `do_masked_loss` is enabled. The wrapper exports aligned sidecars and checks that installed contract. Source alpha is separate from Qwen's RGBA image training. No background replacement, automatic segmentation model, model download, random flip, or synthetic augmentation is enabled by Object preparation.

The [Diffusers advanced LoRA guide](https://huggingface.co/blog/sdxl_lora_advanced_script) discusses custom captions and varied training images. The community/backend guidance above supports retaining user control and comparing outcomes. We use crops to reduce irrelevant pixels, captions to describe remaining changeable context, and optional masks to reduce background loss. None establishes complete disentanglement; repeated props and backgrounds still warrant review. Defaults retain model-specific grid and caption conventions described above.

Live synthetic checks exercised isolated, cluttered, explicitly distinguished, ambiguous, absent and occluded objects with the running local vision provider, plus a multi-image JoyCaption → connected text-formatter pass. Grounding was compared with authored object bounds, and exported masks were loaded by the installed AI Toolkit code. These are integration and preparation checks, not a trained LoRA quality evaluation. Actual local outputs remain under ignored `internal-tests/`.

Tracked tests use synthetic observations, generated geometric images, mocked caption providers and temporary exports. They cover routing, selected model guidance, KEEP/CHANGE filtering, object lettering fidelity, concept relationships, category-specific checks, coverage persistence, stale observation handling and unchanged Person contracts. They do not establish live caption accuracy, successful GPU training or LoRA quality. Real local integration evidence belongs exclusively under ignored `internal-tests/`.
